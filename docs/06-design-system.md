## 1. 왜 바꾸나

적용 전 `src/renderer/styles/index.css`는 tweakcn에서 가져온 shadcn 테마를 거의 그대로 쓴다. 문제는 다음과 같다.

| 문제 | 지금 | 영향 |
|---|---|---|
| 글꼴이 로드되지 않음 | `--font-sans: Plus Jakarta Sans`를 선언만 하고 `body`는 system-ui로 덮어씀. 한글 글리프도 없음 | 토큰과 실제 화면이 다르다 |
| 모서리가 너무 둥금 | `--radius: 1.4rem`(22.4px), `sm`도 18.4px | 문서 도구에 비해 장난감처럼 보이고, 썸네일과 카드가 같은 둥글기다 |
| 간격 단위가 어긋남 | `--spacing: 0.27rem`(4.32px) | Tailwind 간격이 모두 4px 격자에서 벗어난다 |
| 팔레트 클래스가 하드코딩됨 | `bg-black/50`, `bg-black/60`, `text-white`, `border-yellow-500` 등 약 42곳 | 테마를 바꿔도 따라오지 않는다 |
| 상태 색이 없음 | `destructive`뿐 | 완료, 주의 표시가 제각각이다 |
| 비교 기능 색이 없음 | 없음 | Phase 3 비교 뷰어에 쓸 추가/삭제/변경 색이 필요하다 |
| 쓰지 않는 변수 | `chart-*`, `sidebar-*`, `popover*` | 읽는 사람만 헷갈린다 |

## 2. 무엇을 바꾸나

**shadcn 변수 이름은 그대로 둔다.** `shared/ui`(button, dialog 등)가 `bg-primary`, `hover:bg-accent` 같은 클래스를 이미 쓰고 있으므로, 이름을 바꾸면 컴포넌트를 다 고쳐야 한다. 값만 다듬고 필요한 토큰을 더한다.

### 2.1 색

- 중립색은 primary 색상(hue 285)으로 아주 살짝 기울였다.

**제거**: `chart-1`~`chart-5`, `sidebar*`, `popover`, `popover-foreground`(코드에서 쓰지 않음), `--font-serif`(Lora, 쓰지 않음), `--shadow-x/y/blur/spread/opacity/color`(합성용 중간값, 쓰지 않음).

> 다크 값 근거(Step 25): 시안에 다크 화면이 없어 기존 다크 팔레트 규칙에서 정했다. 다크 팔레트는 카드 위의 면(`muted` 0.27, `secondary` 0.29)을 카드(0.245)보다 **밝게** 올리고, 그 간격은 라이트(카드 1 → `muted` 0.955, 0.045)의 약 절반(0.025)이다. `card-inset`은 라이트에서 카드와 `muted` 사이(카드에서 0.025)이므로 다크도 같은 비율로 카드에서 0.014 올린 0.26(채도는 카드와 같은 0.009)이다. `success-subtle`은 옅은 primary 면인 `accent`의 다크 규칙(바탕 L 0.30·낮은 채도, 글자 L 0.84)을 hue 155에 그대로 옮겼다. 글자 대비는 라이트·다크 모두 4.5:1을 넘는다.

> 연결선 색(Step 28-c): 연결선은 늘 종류 색 `diff-insert`·`diff-delete`·`diff-change`이고 두 테마에 같은 값이다. 바탕과의 대비는 라이트 `canvas` 4.15·3.79·3.48:1, 다크 `canvas` 4.10·4.48·4.88:1, 종이(`paper`, 흰색) 4.63·4.24·3.89:1로 모두 3:1(그래픽 요소)을 넘어 다크 값을 따로 두지 않았다. 띠 채움은 종류 `-fill`(알파 0x33·0x40)이다.

> 주의: `success`와 `destructive`는 밝기가 비슷하다. 상태는 반드시 아이콘이나 낱말과 함께 표시한다. 비교 색은 파랑(추가)·주황(삭제)으로 색각 이상에서도 구분되며, 변경은 점선으로 구분한다.

### 2.3 간격, 모서리, 그림자

- **간격**: `--spacing: 0.25rem`(4px). 지금보다 모든 Tailwind 간격이 약 7.4% 줄어든다. **화면 밀도가 바뀌므로 적용 후 주요 화면을 눈으로 확인한다.**
- **모서리**: 역할별 고정값으로 바꾼다. `--radius` 하나에서 계산하던 방식을 버린다.

| 토큰 | 값 | 지금 | 쓰는 곳 |
|---|---|---|---|
| `radius-paper` | 2px | (없음) | PDF 페이지 |
| `radius-xs` | 4px | 2px(Tailwind 기본) | 배지, 체크박스 |
| `radius-sm` | 6px | 18.4px | 입력칸, 툴팁 |
| `radius-md` | 8px | 20.4px | 버튼 |
| `radius-lg` | 12px | 22.4px | 카드 |
| `radius-xl` | 16px | 26.4px | 다이얼로그 |

- **그림자**: 기존 `shadow-xs`~`shadow-xl` 값은 유지하고 `shadow-paper`(페이지 썸네일)를 더한다. 값은 화면 시안 HTML의 종이 그림자 `0px 0px 0px 1px rgba(0, 0, 0, 0.06), 0px 1px 2px 0px rgba(0, 0, 0, 0.12)`다(Step 24에서 홈 카드 그림에 처음 씀).

## 3. FSD 파일 배치

토큰은 앱 전체에 한 번 적용되는 설정이므로 **`app` 레이어**에 둔다. TS에서 토큰 이름이 필요하면 **`shared/config`** 에 상수로 둔다. 토큰을 쓰는 쪽(entities, features, widgets)은 Tailwind 클래스로만 참조한다.

```
src/renderer/
├─ app/
│  ├─ styles/                      # 앱 전역 스타일(fonts, tokens, theme, base)
│  │  ├─ index.css                 # 진입점: tailwind, tw-animate-css, fonts, tokens, theme, base 순서로 import
│  │  ├─ fonts.css                 # @fontsource import (sans 400/500/600, mono 400/500)
│  │  ├─ tokens.css                # :root(light), .dark 의 원시 변수. 디자인 시스템 tokens.json 과 1:1
│  │  ├─ theme.css                 # @custom-variant dark, @theme inline: --color-*, --radius-*, --shadow-*, --font-* 매핑
│  │  └─ base.css                  # @layer base: body, 포커스 링, 선택 영역
│  ├─ providers/
│  │  └─ theme-provider.tsx        # system|light|dark 설정, .dark 클래스 토글 (P1-5)
│  └─ index.tsx                    # import "./styles/index.css"
│
├─ shared/
│  ├─ config/
│  │  └─ theme.ts                  # THEME_MODE, GROUP_COLOR_CLASSES, DIFF_KIND 같은 토큰 이름 상수
│  └─ ui/                          # 토큰 클래스만 사용. 팔레트 클래스(bg-black/50 등) 금지
│
├─ entities/
│  └─ comparison/ui/               # (Phase 3) diff-* 토큰으로 하이라이트 박스
│
└─ features/pdf-merge/
   ├─ ui/                          # 문서·페이지 카드: bg-paper, rounded-paper, shadow-paper, bg-media-scrim
   └─ model/                       # group-colors 는 shared/constants → shared/config/theme.ts 로
```

규칙:
- **`app/styles` 밖에서 CSS 변수를 정의하지 않는다.** 컴포넌트의 `style={{}}`는 크기·위치 계산에만 쓴다.
- **`shared/config/theme.ts`는 이름만 갖는다.** 색 값은 CSS에만 있다(값이 두 곳에 있으면 어긋난다).
- `components.json`의 `tailwind.css`를 `src/renderer/app/styles/index.css`로, 존재하지 않는 `components` 별칭을 `@/renderer/shared/ui`로 고친다.

## 4. 적용 순서

[단계별 진행 가이드](plans/2026-10-step-guide.md)에서 1단계는 Step 2, 2~4단계는 Step 7, 5단계는 Phase 3에 들어 있다. 각 단계는 따로 커밋할 수 있다.

1. **파일 이동**(완료): `src/renderer/styles/` → `src/renderer/app/styles/`로 옮기고 `tokens.css`, `theme.css`, `base.css`로 나눈다. 값은 그대로 둔다(동작 변화 없음). `components.json` 경로를 고친다.
2. **글꼴 번들**(완료): `@fontsource` 두 패키지를 추가하고 `fonts.css`를 연결한다. `body`의 system-ui 덮어쓰기를 지운다.

## 6. 적용 결과와 문서와 다른 점

정본 `tokens.json`을 가져올 수 없어 이 문서의 §2·§3.1 값을 그대로 넣었다. 문서에 없는 값은 지어내지 않고 기존 값을 두었다.

- **배치**: 색은 `tokens.css`(`:root`/`.dark`)와 `theme.css`의 `@theme inline`(`--color-*: var(--*)`), 테마와 상관없는 글꼴·`--spacing`·모서리·그림자·자간은 `theme.css`의 `@theme`(고정값)에 둔다. 다크 블록은 색만 다시 정의한다.
- **글꼴 스택**: §2.2 순서 끝에 일반 글꼴(`sans-serif`, `monospace`)을 하나 더 두었다. `@fontsource` CSS가 `woff2`와 `woff`를 함께 가리켜 빌드에 둘 다 자산 파일로 나간다(작은 파일은 `data:`로 인라인, CSP `font-src 'self' data:` 안).
- **그대로 둔 값**: 그림자 `shadow-2xs`~`shadow-2xl`(기존 값), 자간 `--tracking-normal: -0.025em`과 파생 값(문서에 없음).
- **넣지 않은 것**: 글자 스타일 토큰(§3.1·`theme.css` 설명에 없음). `shadow-paper`와 `paper-line`은 Step 24에서 시안 HTML 값으로 넣었다(§6.1).
- **새 토큰 중 아직 쓰지 않는 것**: `media-scrim`. Step 24-a에서 병합 카드 위 체크박스·동작 버튼이 카드색 막대로 바뀌어 쓰는 곳이 없어졌다(다른 화면에서 쓸지 정한 뒤 지운다). `canvas`·`paper`·`success`·`diff-*`는 홈(Step 24)·병합(Step 24-a)에서 쓴다. `warning`/`-foreground`는 비교 결과의 "확인 필요"(Step 27, §6.5), `media-foreground`는 비교 결과 페이지 위 번호 태그 글자(종류 색 바탕 위 흰 글자, Step 27)에서 쓴다.
- **모서리**: 임의값 `rounded-[4px]`는 같은 4px인 `rounded-xs`로만 바꿨다. §2.3 "쓰는 곳"과 다른 곳이 남아 있다 — 공용 버튼 기본 `rounded-lg`(12px, 문서는 `md` 8px), 다이얼로그 `rounded-xs`(4px, 문서는 `xl` 16px), 페이지 썸네일 `rounded-paper` 미사용(병합 카드 종이는 시안 2·6대로 `rounded-xs` 4px). 병합 화면(Step 24-a)은 공용 버튼 기본값을 바꾸지 않고 `className`으로 8px(`rounded-md`)·6px(`rounded-sm`)를 준다(비교·홈 화면에 영향을 주지 않으려고). 공용 버튼 기본 모서리를 역할대로 맞추는 일은 전 화면을 함께 볼 때 한다.
- **팔레트 클래스 → 토큰** (실제 팔레트 클래스 34개, 임의값 14개): `bg-black/60` → `bg-media-scrim`, `bg-black/50` → `bg-scrim`, `text-white`·`bg-white/20`(썸네일 위 버튼) → `media-foreground`, 오류 화면의 `red-*`·`gray-*` → `destructive`·`muted-foreground`, `group-colors.ts` → `shared/config/theme.ts`의 `GROUP_COLOR_CLASSES`(`border-group-1`~`5`).
- **모양이 바뀐 곳**: 썸네일 위 삭제 버튼 hover는 빨간 글자(`text-red-400`) 대신 `bg-destructive` + `text-destructive-foreground` 채움이다(어두운 막 위에서 라이트 `destructive` 글자는 대비가 모자람). 공용 체크박스 테두리는 `border-white/50` 대신 `border-input`이고(툴바 체크박스가 라이트에서 보이게), 썸네일 위 체크박스만 `border-media-foreground/50`을 넘긴다. Step 24-a에서 카드 위 체크박스·동작 버튼이 어두운 막(`media-scrim`)을 떠나 종이·카드색 막대 위로 옮겼다. 체크박스는 공용 `border-input` 그대로이고 삭제 버튼 hover 채움은 그대로다.
- **남은 임의값**: 크기·위치 계산용 `max-h-[70vh]`, `h-[80vh]`, `h-[calc(100%-48px)]`, `max-w-[calc(100%-2rem)]`, `transition-[left,top]`. 글자 크기 `text-[15px]/5.5`(§2.2 `heading` 15/22, 홈 상단바 앱 이름·비교 슬롯 파일 이름), `text-[13px]`(병합 화면(Step 24-a) 툴바 "전체 선택"·"전체 삭제", 복원 버튼, 진행 단계 %, 비교 슬롯(Step 25) "교체"), `text-[28px]/8`(진행률 큰 숫자, mono), `text-[11px]/3.5`(§2.2 `page-number` 11/14, 펼친 페이지 카드 아래 줄), `text-[10px]`·`text-[11px]`(비교 옵션 범위 칸 A·B 배지, 진행 카드 이름 배지·대기 번호, Step 26), `text-[13px]/4.75`·`text-[11px]`·`text-[10px]/4`(비교 결과 목록 요약·쪽 배지·`#번호`, 캡션 A·B 배지, 페이지 번호 태그, Step 27) — 글자 스타일 토큰이 없어서. 플로팅 바 너비 `max-w-[calc(100%-3rem)]`(시안 2 `calc(100% - 48px)`), 비교 옵션 두 표 `grid-cols-[minmax(0,1.35fr)_minmax(0,1fr)]`(시안 3). 색 임의값은 없다. 크기 토큰은 §5대로 화면을 잰 뒤 정한다.
- **간격**: 그리드 카드 크기·간격은 JS 상수(`shared/constants/grid-layout.ts`, px)라 `--spacing` 변경과 상관없다. Tailwind 간격(패딩·높이)만 약 7.4% 줄었다. Step 24-a에서 그리드는 시안 2(`auto-fill, minmax(180px, 1fr)`, 간격·여백 24px)를 JS로 따라 한다: 확대 막대 값이 최소 열 너비(140~220px, 기본 180px = 100%)이고, 열 수는 그 값으로 정하고 카드 폭은 남는 폭을 나눠 가로를 채운다. 종이 높이는 최소 열 너비 × 220/180, 카드 아래 글 영역은 52px.
- **검증**: `e2e/design-tokens.spec.ts` — 본문 글꼴과 실제 로드, 라이트·다크 본문 대비 4.5:1 이상, 키보드 포커스 링(링 색과 배경 3:1 이상).

### 6.2 병합 화면: 시안 2·6·7·8과 지금 화면

Step 24에서 Playwright 헤드리스 캡처(1280×800)와 시안 PNG를 나란히 놓고 차이를 모았고, Step 24-a(계획서 D10 수정: 구조·기능 유지, 스타일·배치·문구는 시안)에서 맞췄다. 항목마다 **반영** 또는 **유지(이유)**를 적는다. 새 데이터가 필요하거나 동작이 바뀌는 항목은 유지했다.

툴바(시안 2·6)
- 모드 탭 `[병합 | 비교 | 번역]`: **반영**(Step 42, §6.8). 탭 모양은 Step 24부터 같다.
- "전체 선택": **반영** — 체크박스 + "전체 선택" 글자(13px), 패딩 6/10px·모서리 6px. 글자가 보이므로 툴팁은 뺐다.
- "전체 삭제": **반영** — 13px 보통 굵기·모서리 6px·아이콘 간격 6px.
- "파일 추가"·"병합": **반영** — 높이 36px·모서리 8px·굵기 500, 좌우 16px(병합 20px).
- 머리: **반영** — `min-height: 64px` + 줄바꿈, 좌우 무리 최소 폭 260px·160px.

카드 그리드(시안 2·6)
- 배치: **반영** — `auto-fill, minmax(180px, 1fr)`·간격·여백 24px처럼 가로를 채운다(1280에서 6열). 확대 막대는 최소 열 너비를 바꾼다(§6 "간격"). 절대 좌표·dnd-kit·드롭 위치 계산은 그대로 쓴다. 작업 영역 바탕 `canvas`, 아래 여백 120px.
- 종이: **반영** — `paper` 바탕 + `shadow-paper` + 모서리 4px, 뒤에 깔린 종이(테두리). 페이지 그림은 회전해도 종이 안에 들도록 정사각형 상자(종이 짧은 변 − 16px)에 그린다. 시안처럼 종이를 꽉 채우지는 않는다 — **유지**(이유: 90°·270° 회전 썸네일이 상자를 넘지 않게 하는 기존 방식, 바꾸면 회전 표시 동작이 바뀐다).
- 선택 표시: **반영** — 고른 카드는 2px primary 테두리 + 20px primary 체크 사각형, `media-scrim` 바탕은 뺐다.
- 고르지 않은 카드의 체크박스: **유지**(이유: 마우스·키보드 포커스로 보이는 동작을 E2E `selection.spec.ts` "키보드 포커스가 카드에 있으면 카드 버튼이 보인다"가 고정한다). 시안 6은 펼친 페이지 카드의 빈 체크박스를 늘 보인다.
- 체크박스 테두리: 시안 1.5px, 앱은 공용 체크박스 1px `input` — **유지**(이유: 1.5px 토큰이 없고 임의값을 늘리지 않는다).
- 카드 위 동작 버튼(펼치기·삭제, 펼친 카드의 접기·미리보기·회전·삭제)과 가운데 미리보기 확대 버튼: **유지**(시안에 없는 기능 진입점). 모양만 시안 언어로 — `media-scrim` 막 대신 카드색 막대 + 테두리 + `shadow-sm`, 버튼 모서리 8px, 확대 버튼은 카드색 원.
- 카드 아래 둘째 줄: **반영** — 쪽수 "5페이지". 삭제·나뉜 그룹처럼 일부만 남으면 "4페이지 (1-2, 4-5)".
- 펼친 페이지 카드 아래 줄: **반영** — mono 11/14px 한 줄 "invoice.pdf · p. 1". 파일 이름은 확장자까지 그대로 둔다(이름이 길면 이름만 줄임). 시안은 확장자를 뺀 "invoice" — **유지**(이유: 경로·이름 문자열을 나누지 않는다).
- 파일 그룹 테두리: **반영** — 2px.
- 펼친 그룹 첫 카드의 뒤에 깔린 종이: **유지**(이유: 그룹 시작을 알리는 기존 표시, 시안 6에는 없다).

  - "연결선" 체크박스와 거터의 곡선, 상태바 "연결선 2개": Step 28에서 넣었다(§6.6). Step 27은 거터 폭(세로 120px, 한쪽이라도 가로 쪽이면 72px, 계획서 §7.1)과 자리(`data-connector-gutter`)만 두었다. Step 28-c부터 거터는 두 패널 사이 120px 하나다(§6.6).
  - "내보내기": Step 29. 막힌 버튼으로 자리만 둔다.
  - ⋯: 메뉴 하나("다시 실행", Radix DropdownMenu, `shared/ui/dropdown-menu.tsx`). 같은 문서·지금 옵션으로 다시 비교한다.
  - 모드 탭 번역·상태바 "오픈소스 라이선스"는 §6.3과 같다.
- **시안에 없는 것(앱이 정함)**:
  - "확인 필요" 칩: 종류 칩 뒤에 같은 칩 모양으로 둔다(확인 필요가 하나라도 있을 때만). 견본은 `warning` 채움 + `warning-foreground` 점 테두리. 개수는 숨기지 않은 종류의 확인 필요 수(ADR 0001 §5 "종류 필터는 두 개수에 똑같이")이고, 종류 칩 개수는 그 종류의 차이만 센다(확인 필요 제외, 필터와 상관없다). 칩을 끄면 확인 필요만 숨긴다.
  - "확인 필요" 페이지 표시: 종류 색 상자는 그대로 두고 3px 바깥에 `warning-foreground` 1.5px 점 고리(`1.5 2.5`)를 두르고, 번호 태그를 `warning` 바탕 + `warning-foreground` 글자로 바꾼다. 색만이 아니라 모양(점 고리)으로도 차이와 구별된다. 목록 항목에는 `warning` "확인 필요" 배지, 목록 머리에 "확인 필요 N건"(회색), 상태바에 "차이 N건 | 확인 필요 M건". 새 토큰은 만들지 않았다.
  - OCR 배지: 쪽 캡션에 "OCR"(`muted` 배지, 시안 "B만" 배지와 같은 모양), 목록 묶음 머리에는 행의 쪽이 모두 OCR이면 "OCR", 한쪽만이면 "B OCR". 안내 띠에 "OCR로 읽은 쪽 B 3개".
  - 안내 띠 문구: 뺀 반복 줄("머리말과 꼬리말을 양쪽에서 뺐어요", 실행할 때의 옵션), OCR로 읽은 쪽 수, `notices`(글자층 품질 낮음 · 글자층 없음(OCR 없음/실패) · 바뀐 곳이 많아 통째로 표시). 안내가 없으면 띠가 없다. "자세히"를 누르면 줄마다 펼치고 "접기"로 닫는다.
  - 빈 상태: 차이가 없으면 목록에 `success-subtle` 원 + 체크 + "차이가 없어요"(쪽은 그대로 보인다), 필터로 모두 숨기면 "모든 차이를 숨겼어요" + "필터 초기화", 쪽을 받기 전에는 종이 위 `muted` 맥박 스켈레톤(`aria-busy`). 빠르게 스크롤하는 동안 지나가는 행은 빈 자리만 둔다.
  - 짝 없는 쪽: 반대편 자리에 같은 크기의 `input` 점선 + `card-inset` 상자 "A에 없는 쪽이에요". 캡션은 배지 + 파일 이름만.
  - 목록 접기 레일: 너비 44px, 펼치기 버튼과 보이는 차이 수(mono 11px).
  - 현재 쪽: 페이지 영역 세로 가운데에 걸친 행의 쪽. A만 보기는 A 문서, 나란히·B만은 B 문서 기준이고, 그 행에 그 문서 쪽이 없으면 "– / 19쪽".
  - 미니맵 눈금: 변경이 속한 행 안에서 변경 순서대로 고르게 나눈 자리(쪽 안 정확한 세로 위치는 pdf.js가 그 쪽을 열어야 알 수 있어 쓰지 않는다, ADR 0001 §2).
  - 옵션 화면 머리 "최근 결과"(시안 3: 테두리 버튼, 그려진 높이 34px): 남은 결과가 있을 때만 보이고 결과 화면으로 간다.

### 6.6 비교 결과 연결선: 시안 4와 지금 화면 (Step 28 → 28-c → 28-d)

Playwright 헤드리스(WebKit, 1280×800, 기기 픽셀 비율 1) 캡처를 시안 PNG(`docs/resource/design/04-compare-result.png`)와 나란히 보고 시안 HTML의 연결선·체크박스·상태바 마크업 값과 맞췄다. Step 28-c·28-d 캡처는 연결선 끝점 픽스처(`connector-geometry-a.pdf`·`-b.pdf`)로 시드했고 라이트·다크 둘 다 봤다(28-d는 비교 PDF 미리보기 장도 봤다). 툴바·목록·상태바 배치는 시안을 따르고, **연결선 모양은 사용자 명세(계획서 §7.1, 2026-10-13)가 시안보다 우선한다.**

- **같은 곳**: 툴바 종류 칩 뒤 "연결선" 체크박스(기본 켬, 칩과 16px 간격), A·B 사이 거터 120px, 상태바 "차이 N건 | 연결선 N개", 쪽 캡션·종이 배치(동기 스크롤이 켜져 있으면 시안처럼 같은 쌍의 A·B 쪽이 같은 높이), 고른 변경의 선이 그 종류 색 3px.
- **다른 곳(사용자 명세·Step 범위)**:
  - 선이 거터 안에만 있지 않다(Step 28-d): 변경 끝마다 쪽 너비 전체를 덮는 **줄 표시**(끝 사각형의 세로 범위)가 A·B에 있고, 선은 줄 표시의 세로 가운데에서 쪽 끝(A 오른쪽·B 왼쪽) → 패널 끝까지 수평 → 거터 3차 베지어 → 패널 끝 → 쪽 끝이다. 시안은 거터 x 0 → 120 대칭 S 곡선이고 줄 표시가 없다. Step 28-c는 상자 끝점(A 오른쪽 변·B 왼쪽 변 가운데, 앵커는 막대 가운데)에서 짧은 stem이 나가 지저분해 보였다(사용자 지시 2026-10-13으로 대체).
  - 줄 표시: 종류 선 색(`diff-insert`·`diff-delete`·`diff-change`) 1px 실선 테두리 + 종류 `-fill`을 불투명도 0.5로 채움(라이트·다크 같은 토큰). 낱말 하이라이트(`-fill` 그대로)가 그 위에 더 진하게 보인다. 가리키거나 고르면 테두리 2px. 연결선 체크박스를 끄면 함께 숨는다. 90·270도 쪽의 앵커 줄 표시는 높이 0이라 쪽을 가로지르는 1px 선이다.
  - 평상시도 종류 색(`diff-*`) 1.5px다. 시안은 `connector` 45% 2px 중립색이고 고른 변경만 종류 색이다. 토큰 `connector`는 쓰는 곳이 없어 지웠다(§2.1).
  - 2줄 넘는 블록 변경은 띠(종류 `-fill` 채움 + 같은 색 1px 테두리)다. 시안에 없다.
  - 추가·삭제도 반대편 앵커(글자가 들어갈 자리)에 잇는다. 시안은 변경만 잇는다.
  - A·B 두 패널이 따로 스크롤한다(시안: 한 스크롤). 툴바 "연결선" 뒤에 "동기 스크롤" 체크박스(같은 모양·12px 글자, 16px 간격, 기본 켬)를 더했다.
  - 상태바 "연결선 N개"의 N은 변경 수(이을 수 있는 보이는 변경, 문서 전체)다. Step 28은 묶음 수였다.
  - 체크박스가 16px(시안 14px, 공용 `Checkbox` — "쪽별로 묶기"와 같다). 시안의 "75%"·"연결선 2개"는 예시 값이다.
- **시안에 없는 것(앱이 정함)**:
  - 한쪽 끝만 화면 밖: 그 끝을 패널 위·아래 경계에서 8px 들여놓은 자리로 끌어와 흐린 점선(불투명도 0.45, 대시 `2 4`, 띠도 선으로)과 그 끝 x에 V자 방향 표시(반 폭·높이 4px, 밖인 쪽을 가리킨다)로 그린다. 누르면 그 변경을 골라 그 끝 패널이 돌아온다. 두 끝이 모두 밖이면 그리지 않는다.
  - 가리키기: 거터 구간의 투명한 14px 선(띠는 거터 구간 면)이 마우스를 받는다(쪽 위·스크롤바 위 조작을 가리지 않는다). 선은 3px(띠 테두리 2px)가 되고, 양쪽 상자에 고른 변경 고리와 같은 자리의 옅은 primary 고리(`primary` 50%, 3px), 목록 항목에 `muted` 바탕을 둔다. 누르면 그 변경을 고른다.
  - 스크롤하는 동안에도 연결선이 프레임마다 따라온다(Step 28의 140ms 숨김을 없앴다).
  - A만·B만 보기는 패널 하나라 거터·연결선이 없고 두 체크박스를 막는다(불투명도 0.5).
  - 다크: 종류 색·띠 채움은 두 테마에 같은 값이고 다크 `canvas`·흰 종이 위에서 모두 3:1을 넘는다(§2.1 주석).
- **비교 PDF 연결선(내보내기)**: 선 = 종류 선 색(`diff-insert` `#1f6feb` · `diff-delete` `#d4500f` · `diff-change` `#a67a00`) 1pt 둥근 끝, 띠 = 종류 `-fill`(`#1f6feb33` · `#d4500f33` · `#e0a80040`, 알파 그대로) 채움 + 같은 종류 선 색 0.5pt 테두리. 화면 띠 채움과 같은 토큰이다. 줄 표시(Step 28-d) = 놓인 쪽 너비 전체, 종류 선 색 0.5pt 테두리 + 종류 `-fill` 반 알파(`#1f6feb19` · `#d4500f19` · `#e0a80020`) 채움, 변경 상자 아래. 선은 쪽 끝 → 칸 끝 수평 → 칸 사이 베지어. Step 28은 `connector` 45% 1pt였다.
- **번호 태그 겹침(작은 배율)**: 태그는 화면 px 고정 크기(mono 10/16, 좌우 4px, 상자 오른쪽 6px·위 2px)라 배율을 줄이면 이웃 줄의 태그가 겹쳐 읽을 수 없다(맞춤 배율도 가로 쪽이 낀 문서에서는 29%까지 내려간다). 규칙: 쪽마다 고른 변경의 태그를 먼저, 그다음 번호 순서로 놓으면서 이미 놓은 태그와 겹치는 태그는 그리지 않는다. 태그 너비는 숫자 한 글자 6px(IBM Plex Mono 0.6em)로 어림해 실제보다 조금 넓게 본다. 상자 하이라이트는 그대로 두므로 변경 위치는 다 보이고, 빠진 번호는 목록·이전/다음으로 찾는다. 배율을 키우면 다시 보인다(`widgets/compare-viewer/lib/number-tag-layout.ts`, E2E `compare-connectors.spec.ts`가 25%에서 겹침 없음·100%에서 모두 보임을 확인).

### 6.7 비교 결과 내보내기: 시안 5와 지금 화면 (Step 29)

Playwright 헤드리스(WebKit, 1280×800, 기기 픽셀 비율 1) 캡처를 시안 PNG(`docs/resource/design/05-compare-export.png`)와 나란히 보고 시안 HTML의 마크업 값과 맞췄다. 결과는 pages-base ↔ pages-insert 시드, 미리보기 그림은 E2E mock이 그린 장 번호 PNG다(앱에서는 Rust가 그린 장).

- **같은 곳**: 막(`scrim`), 모달(너비 1040px·모서리 16px·`shadow-xl`·카드색, 1280×800에서 화면 가운데 1040×571 — 시안 HTML을 같은 브라우저로 그린 상자와 같다, 세로 위치는 반올림으로 1px 안), 머리(패딩 22/28/14px, "PDF로 내보내기" 18/26 600, "지금 보이는 필터 그대로 내보내요 · 용지는 A4 가로" 12/17 `muted-foreground`, 닫기 32px 모서리 8px + 18px ✕), 본문(`1fr | 360px` 칸 사이 24px, 아래 20px), "받을 파일" 13px 600, 비교 PDF 카드(고르면 `primary` 테두리 + 3px `accent` 고리, 모서리 12px, 패딩 14/16px, 16px 체크박스, 제목 600 + 12/17 설명), 하위 옵션(왼쪽 28px·2px `border` 선, 쪽 구성 `secondary` 바탕 26px 칸·고른 칸 카드색 500, 13px 체크 줄 + mono 12px "(6쪽 → 3쪽)"), 주석 PDF 카드, "저장 위치"(36px `muted` 칸 mono 12px 말줄임 + 36px 테두리 "바꾸기" 13px, "만들 파일: " + mono 이름), 미리보기 칸(`canvas` 바탕·모서리 12px·패딩 14px, "미리보기" 600 + mono "1 / 3장", 26px 이전·다음, A4 가로 비율 종이 `paper`·`radius-paper`·`shadow-paper`, 12/17 안내), 바닥(`border` 위 선, 패딩 14/28/22px, 13px 문구 / 42px 테두리 "취소"(시안은 content-box라 높이 40px에 테두리 2px가 더해진다, §6.3) / 40px `primary` "내보내기" + 16px 내려받기 아이콘). 왼쪽 칸 600×391·미리보기 칸 360×391(x 772)·바닥 79px도 시안 상자와 같다.
- **다른 곳**:
  - 저장 위치: 시안은 처음부터 "~/Documents/PDF Studio/비교 결과"가 있지만, 앱은 고르기 전에는 "아직 고르지 않았어요" + "고르기"이고 고른 폴더는 전체 경로(`~` 줄임 없음)다. 허용 경로 목록(D13)상 사용자가 고르지 않은 폴더에는 쓰지 않는다(계획서 P3-5 "Step 29에서 정한 것").
  - 미리보기 장: 시안은 장 위에 "공급계약서 v1 → v2 · 3쪽" 캡션과 가짜 글줄이 있지만, 앱은 Rust가 그린 실제 장(캡션 없음 — 장 위 글자는 한글 글꼴 임베드가 필요해 넣지 않는다, ADR 0001 §14 "빈 칸")이다. 장 그림은 종이 칸에 비율을 지켜 들어간다.
  - 이전·다음은 시안의 "‹ ›" 글자 대신 14px 화살표 아이콘(앱의 다른 이전·다음과 같다).
  - 시안 "(19쪽 → 6쪽)"·"1 / 6장"·"(변경 숨김)"·"파일 1개를 만들어요"는 예시 값이고 앱은 그 결과·필터·고른 것의 값이다.
  - 자간은 앱 전역 `-0.025em`이라 글자가 조금 좁다(§6.1).
- **시안에 없는 것(앱이 정함)**:
  - 바닥 줄 이유 문구("받을 파일을 하나 이상 골라 주세요." · "저장할 폴더를 골라 주세요." · "지금 필터로는 비교 PDF에 넣을 쪽이 없어요.")는 옵션 카드처럼 `destructive` 글자이고 내보내기를 막는다(불투명도 0.5).
  - 비교 PDF를 끄면 카드가 `border` 테두리로 돌아가고 하위 옵션을 막으며(불투명도 0.5), 미리보기 자리에 `input` 점선 + `card-inset` 상자 "미리보기는 비교 PDF만 보여요."를 둔다. 넣을 장이 없을 때("지금 필터로는 넣을 쪽이 없어요.")와 그리지 못했을 때(+ 오류 코드 문구)도 같은 상자다. 종이(`paper`)는 두 테마 모두 흰색이라 글자를 종이 위에 두지 않는다.
  - 받는 중: 종이 위 `muted` 맥박 스켈레톤(`aria-busy`), 장 수·넘기기는 받은 뒤에 보인다.
  - 내보내는 중: 내보내기 버튼이 회전 아이콘 + "내보내는 중…"으로 막히고, "바꾸기"도 막힌다. 끝나면 sonner 성공 토스트 "PDF 2개를 만들었어요" + 만든 이름, 실패는 오류 토스트 "비교 PDF를 만들지 못했어요." + 코드 문구.
  - 다크 테마: 카드·`canvas`·`muted`·`accent` 고리가 다크 값으로 바뀌고 종이·장 그림은 흰색 그대로다(새 토큰 없음).
