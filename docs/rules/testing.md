# 테스트 규칙

언제 읽는가: 테스트를 쓰거나 고칠 때, 리팩터링 전에 동작을 고정할 때, 어떤 테스트를 둘지 판단할 때.

- **Rust는 핵심 동작만 테스트한다.** 결과가 바뀌면 깨지는 규칙이 대상이다: 병합(페이지 순서·회전 절대값·북마크), 정보 읽기, TIFF 변환, 비교 엔진(추출·토큰화·diff·앵커·쪽 짝짓기·연결선 끝·모양·리포트 내보내기), 번역 문단 추출, 번역 규칙(묶음·예상치·요청·응답·재시도·실행기·이어하기 기록·계획·다시 번역·고치기), 번역 커맨드 검증(검사 순서·키를 응답·로그·`AppError`에 싣지 않음, ADR 0002 §10 "Step 41 구현에서 정한 것"), 경로 검증, 진행률 계산. `crates/pdf-core`와 `src-tauri`의 순수 로직에 적용한다.
- **Rust에서 쓰지 않는 테스트:** 상수 값 확인, 단순 getter, 자명한 enum↔문자열 매핑, 라이브러리(pdfium 등) 자체 동작, 다른 테스트와 같은 것을 다시 확인하는 중복. 「이 테스트를 실패시킬 production 변경」을 한 줄로 말할 수 없으면 쓰지 않는다.
- Rust 핵심 코어는 **Red → Green → Refactor.** 실패하는 테스트를 먼저 쓰고, 통과시키는 최소 코드를 쓰고, 그다음 정리한다. 버그는 재현 테스트부터 쓴다.
- 비교 엔진·연결선 끝·모양은 golden JSON 픽스처로 Rust에서 검증한다.
  - golden은 `crates/pdf-core/tests/golden/`에 둔다. 픽스처나 규칙을 바꾸면 `UPDATE_GOLDEN=1 PDFIUM_LIB_PATH=<라이브러리 파일> cargo test -p pdf-core --test <테스트 파일>`로 다시 쓰고, 바뀐 값을 눈으로 확인한 뒤 E2E까지 통과시킨다. 비교 픽스처는 `crates/pdf-core/tests/fixtures/generate_compare_fixtures.py`로 만든다(한글 글꼴을 `node_modules`의 OFL 글꼴에서 읽으므로 `pnpm install` 뒤에 돌린다).
  - 좌표 golden 픽스처는 글꼴을 임베드한다(OS 글꼴 대체로 tight box가 달라짐).
  - 앵커·같은 줄 상자 병합(Step 28-b, ADR 0001 §4·§10)은 `compare_placement.rs`가 golden(`placement.changes.json`)과 함께 확인한다. 기대 앵커·상자는 추출 글자(`extract_text_layer`)의 tight 상자를 테스트 안에서 합쳐 세운다(토큰화·diff·앵커 코드를 거치지 않은 값). `diff_tokens`를 직접 부르는 테스트는 비교 범위 쪽과 쪽 크기(`ComparedPages`)를 함께 넘긴다.
  - 연결선 끝·모양(Step 28-c, 계획서 §7.1)은 `compare_connectors.rs`가 golden(`connector-geometry.connectors.json`, 행·쪽 크기를 함께 담아 E2E가 그대로 시드한다)과 종류·글자·모양·끝 쪽을 적은 리터럴로 확인하고, 줄 수 경계·첫 쪽 상자만 합치기·쪽이 없는 끝은 `connectors.rs` 단위 테스트가 손으로 만든 상자로 확인한다. 비교 PDF 연결선과 삭제 메모 자리는 `report/tests.rs`다.
  - 번역 문단 추출(Step 37, ADR 0002 §2)은 `tests/paragraphs.rs`가 golden(`paragraphs-*.paragraphs.json`)으로 확인한다. 픽스처는 `generate_paragraph_fixtures.py`로 만든다(표준 라이브러리만 쓰고, 글꼴은 `fixtures/fonts/`에 커밋한 Noto Sans SC·TC 서브셋(OFL)이라 `pnpm install`이 필요 없다). 픽스처 문장에 서브셋에 없는 글자를 넣으면 스크립트 머리말의 fontTools 명령으로 서브셋을 다시 만든다. 목록 머리 경계·줄 잇기는 `paragraphs/text.rs` 단위 테스트다.
  - 시간에 따라 달라지는 동작(diff 시간 제한)은 이미 지난 제한(`Duration::ZERO`)으로 결정적으로 확인한다. 실제 시간을 재서 단언하는 테스트는 두지 않고, 측정값은 ADR·상수 주석에 남긴다.
  - 해시처럼 규칙으로 계산하는 값(`Change.id`)은 기대값을 테스트 대상 코드가 아닌 다른 구현(Python `hashlib` 등)으로 구해 리터럴로 둔다.
- OCR 비교 테스트(`crates/pdf-core/tests/compare_ocr.rs`, 실행기의 스캔 쪽 테스트 `compare_runner.rs`)는 `tests/ocr.rs`처럼 `ONNXRUNTIME_LIB_PATH`·`OCR_MODEL_DIR`이 없으면 건너뛴다(런타임 없이 도는 `OcrUnavailable` 테스트만 남는다). OCR golden(`ocr-edit.changes.json`)은 변경의 종류·글자·확인 필요만 담는다(상자·신뢰도는 OCR 실행 환경에 따라 조금 흔들릴 수 있어 빼고, 상자는 허용 오차 테스트로 따로 본다). debug 빌드에서 OCR 테스트 파일 하나가 약 1분 걸린다. CI는 세 OS 잡 모두 두 값을 넣어 OCR 테스트를 돌린다(`.github/workflows/ci.yml`). 신뢰도·확인 필요·NFKC 강제 규칙은 pdfium·OCR 없이 글자를 직접 만든 문서로 확인한다(`compare_review.rs`). OCR 픽스처는 `generate_ocr_fixtures.py`로 다시 만든다.
- **프론트는 새 단위 테스트(Vitest)를 쓰지 않는다.** 검증은 Playwright E2E로 한다: Vite dev 서버 + `mock-platform` + WebKit 엔진 헤드리스(창이 뜨지 않는다). 어댑터(`tauri-platform.ts`)에도 단위 테스트를 따로 두지 않고 계약 타입과 typecheck로 형태를 맞추고 동작은 E2E로 확인한다.
- 기존 프론트 Vitest(특성 테스트 포함)는 리팩터링 중 동작 고정용으로 유지한다. 대상 코드를 다시 쓰거나 지우는 Step에서 같은 동작을 E2E가 확인하게 되면 그 테스트도 함께 지운다.
- 공개 인터페이스로 테스트한다. 구현 세부(private 함수, 내부 상태)를 테스트하지 않는다.
- 위치: Rust 단위 테스트는 같은 파일 `#[cfg(test)] mod tests`(길면 모듈 폴더의 `tests.rs`), 통합 테스트는 `crates/*/tests/`, 픽스처는 `crates/pdf-core/tests/fixtures/`, E2E는 `e2e/`. 기존 Vitest는 대상과 같은 폴더의 `__tests__/`에 있다. 만든 PDF를 pdfium으로 다시 열어 객체·주석을 봐야 하는 테스트(리포트 내보내기 `compare/report/tests.rs`)는 pdfium 핸들이 crate 안에서만 보이므로 crate 안 테스트로 둔다. 테스트가 pdfium을 직접 쓸 때도 `engine().session()`(pdfium 프로세스 잠금, ADR 0001 §15)으로 연다(`inspect_output`). 세션을 쥔 채 pdf-core 공개 함수(추출·렌더·내보내기)를 부르면 같은 잠금을 다시 잡아 멈추므로, 공개 함수는 세션 밖에서 부르고 세션 안에서는 읽은 값만 모아 나온다. 그래서 테스트끼리 병렬로 돌아도 된다(Step 28의 테스트 잠금 `pdfium_serialized`는 지웠다).
- **pdfium 동시 호출(Step 29):** `crates/pdf-core/tests/pdfium_concurrency.rs`가 12스레드 × 20회로 비교 PDF·주석 PDF 내보내기·미리보기·추출·정보 읽기를 섞어 돌리고, 결과가 한 스레드로 돌린 기준과 같은지(미리보기 PNG는 바이트까지) 본다. pdfium 잠금을 빼면 프로세스가 SIGSEGV로 죽는다(30번 중 29번). 죽어도 다른 테스트 파일에 번지지 않게 통합 테스트 파일 하나로 둔다.
- **E2E 실행:** `pnpm test:e2e`. `playwright.config.ts`가 E2E 전용 포트(기본 1430, 환경변수 `E2E_PORT`로 바꾼다)로 Vite 개발 서버(`pnpm dev:web`)를 띄우고 WebKit 헤드리스 프로젝트 하나로 `e2e/*.spec.ts`를 돈다. 처음 한 번 `pnpm exec playwright install webkit`. 실패하면 `test-results/`에 trace가 남는다(`pnpm exec playwright show-trace <trace.zip>`). 병렬 worktree에서 동시에 돌리면 worktree마다 `E2E_PORT`를 다르게 준다(예: `E2E_PORT=1436 pnpm test:e2e`). 같은 포트면 뒤에 뜬 서버가 `--strictPort`로 실패한다.
- **E2E 시드·기록:** 브라우저에는 실제 파일이 없으므로 테스트가 `page.addInitScript`로 `window.__E2E_MOCK_SEED__ = { files }`를 넣는다. 파일마다 경로·표시 이름·쪽별 `PageInfo`(크기·원본 회전)·썸네일용 PDF 바이트(base64)를 준다. PDF는 `e2e/fixtures/`의 작은 합성 파일(`crates/pdf-core/tests/fixtures/` 사본, 또는 같은 폴더의 표준 라이브러리 Python 생성 스크립트로 만든 것 — 예: `generate_korean_cid.py`)만 쓰고 실제 문서는 쓰지 않는다. 앱은 쓰기 계열 호출(`mergePdfs`·`copyFile`·`discardTemp`)을 위임 전에 `window.__E2E_MOCK_WRITES__`에, `readPdf`로 읽은 경로를 `window.__E2E_MOCK_READS__`에 기록하고, pdf.js 캐시 상태(destroy되지 않은 문서 경로, 렌더 캐시 항목)를 `window.__E2E_PDF_CACHE_STATS__()`로 내준다. 창 밖 파일 드래그·드롭은 `window.__E2E_FILE_DROP__(event)`로 흉내 낸다(Tauri `onDragDropEvent` payload와 같은 모양, 좌표는 물리 픽셀 = CSS 픽셀 × `devicePixelRatio`). mock은 드롭 경로를 구독자에게 알리기 전에 허용 목록에 기록한다(Rust와 같은 순서). 테스트는 `page.evaluate`로 읽는다. 구현은 `app/providers/e2e-platform.ts`이고 개발 서버에서만(`import.meta.env.DEV`) 쓰여 프로덕션 번들에는 들어가지 않는다.
- **E2E 실패 주입·진행률·취소:** 시드에 `failures`와 `mergeScripts`를 넣는다(코드는 바인딩의 `ErrorCode` 값). `failures.openFiles`는 `{ 경로: 코드 }`로 그 파일만 `openFiles` 파일별 오류로 돌려주고, `failures.copyFile`은 `copyFile`을 그 코드로 실패시킨다. `mergeScripts`는 `mergePdfs`를 부를 때마다 앞에서부터 하나씩 써서 `progress`(Rust와 같은 `MergeProgress` 값, 손으로 셈한 값)를 차례로 보낸 뒤 `failCode`가 있으면 그 코드로 실패하고(`failPath`는 Rust `AppError.path`, 바인딩에 없는 코드도 넣을 수 있다), 다 쓰면 그대로 성공한다(실패 → "다시 시도" 성공 흐름). 진행 화면은 `window.__E2E_HOLD_MERGE__`(Promise)와 `__E2E_RELEASE_MERGE__`(푸는 함수)로 붙잡아 확인하고, 붙잡힌 동안 같은 작업 ID로 `cancelJob`이 오면 Rust처럼 `CANCELLED`로 실패한다. `cancelJob` 호출도 `__E2E_MOCK_WRITES__`에 `{ method: "cancelJob", jobId }`로 남는다. 시드 오류의 `message`는 `E2E 시드 실패: …`라서 화면에 새어 나오면 단언으로 잡을 수 있다.
- **E2E 비교 실행(Step 26):** 시드 `compareScripts`는 `comparePdfs`를 부를 때마다 앞에서부터 하나씩 써서 `progress`(Rust 실행기와 같은 `CompareProgress` 값, ADR 0001 §15 공식으로 손으로 셈한 값. `jobId`는 앱이 보지 않아 아무 값)를 차례로 보낸 뒤 `failCode`(`failPath`)가 있으면 그 코드로 실패하고, 아니면 mock 비교를 거쳐 `result`를 돌려준다. `result`는 계약 JSON과 모양이 같아 Rust golden(`crates/pdf-core/tests/golden/*.changes.json`)을 그대로 넣을 수 있고, 없으면 mock이 차이 없는 결과(두 범위를 차례로 짝지은 행, 출처 `textLayer`)를 만든다. mock 비교는 Rust처럼 고르지 않은 파일을 `PATH_NOT_ALLOWED`, PDF가 아닌 파일을 `UNSUPPORTED_FILE_TYPE`, 쪽 범위 오류를 경로 없는 `INVALID_RANGE`로 거부하고 마지막에 `alignPages` 100% 진행률을 보낸다. 진행 화면은 `window.__E2E_HOLD_COMPARE__`(Promise)와 `__E2E_RELEASE_COMPARE__`로 붙잡고(스크립트 진행률을 보낸 뒤 붙잡는다), 붙잡힌 동안 같은 작업 ID로 `cancelJob`이 오면 `CANCELLED`로 실패한다. 앱이 보낸 비교 요청(옵션 포함)은 `window.__E2E_MOCK_COMPARES__`에 차례로 남는다(`compare-run.spec.ts`).
- **E2E 비교 결과(Step 27):** `compare-result.spec.ts`는 홈 비교 카드에 두 파일을 놓고 실행해 시드 결과(`compareScripts[].result`)로 결과 화면을 연다. 결과는 Rust golden(`diff-edit.changes.json`, `pages-insert.page-pairs.json`, `text-geometry.extract.json`)과 같은 폴더의 픽스처 PDF를 사본 없이 읽어 만든다. 하이라이트 위치는 앱의 SVG 사각형 화면 상자를, 개발 서버의 `pdfjs-setup.ts`를 `import()`해 같은 픽스처를 화면에 놓인 쪽 그림 너비의 배율로 연 pdf.js 텍스트 항목 사각형(항목 transform·width·ascent/descent, `text-box-geometry.spec.ts`와 같은 방법 — 앱의 viewport 변환과 다른 길)과 허용 오차(3pt × 배율 × UserUnit + 테두리 1px) 안에서 맞댄다(CropBox 오프셋·MediaBox 원점·회전 90/180/270·UserUnit 2·교집합 없는 CropBox). 쪽을 받기 전 스켈레톤은 `window.__E2E_HOLD_READ_PDF__`(Promise)와 `__E2E_RELEASE_READ_PDF__`로 `readPdf`를 붙잡아 본다. 행 가상화는 100쪽 픽스처(`e2e/fixtures/hundred-pages.pdf`, `generate_hundred_pages.py`)로 렌더 캐시 항목 수(`__E2E_PDF_CACHE_STATS__`)가 화면 근처 행만큼인지, 멀리 건너뛰어도 사이 행을 그리지 않는지 본다. 하이라이트·미니맵 눈금은 장식이라(`aria-hidden`) 역할이 없어 변경 키 속성(`rect[data-change-id][data-side]`, 확인 필요는 `data-review="true"`)으로 찾고, 거터 자리는 `data-connector-gutter`다. Step 28-c부터 나란히 보기는 A·B 두 패널(`getByRole("group", { name: "A 문서" | "B 문서" })`)이고 행(`getByRole("group", { name: "A 1쪽 · B 1쪽" })`)은 패널마다 있어 패널로 좁혀 찾는다.
- **E2E 연결선(Step 28-c):** `compare-connectors.spec.ts`는 Rust golden(`connector-geometry.changes.json`·`connector-geometry.connectors.json`)과 같은 폴더의 픽스처 `connector-geometry-a.pdf`·`-b.pdf`(회전 0·90·180·270·CropBox 오프셋·MediaBox 원점)로 결과를 시드한다. 변경마다 목록에서 골라 연결선(`[data-connector-layer] g[data-change-id]`)이 `data-state="shown"`이고 `data-shape`가 golden 모양이며, 그린 경로(`path[data-part=line|band]`의 `d`)의 끝점(띠는 네 모서리)이 golden 끝 사각형을 pdf.js 배율 1 viewport로 바꿔 쪽 그림 너비 비율로 놓은 자리(앱의 쪽 변환·쪽 배치·스크롤 계산과 다른 길)와 1px 안인지 배율·창 크기를 바꿔 가며 본다. 좌표 변환·경로·컬링 순수 함수는 개발 서버 모듈(`widgets/compare-viewer/lib/connector-geometry.ts`)을 `import()`해 손으로 정한 입력(경계값 포함)으로 확인한다(화면 스크롤로는 경계에 정확히 맞출 수 없다). 컬링·클램프는 동기 스크롤을 끄고 한 패널만 옮겨 `data-state`(`hidden`·`shown`·`clamped`)·`data-clamped-side`·`data-clamp-edge`·점선(`stroke-dasharray`)·방향 표시(`path[data-part=marker]`)로, 누르기·가리키기는 거터 구간 경로(`path[data-part=hit]`)로 본다. 같은 경계로 모인 점선끼리 겹치므로 점선 누르기는 보이는 끝 쪽(거터 왼쪽 끝)을 마우스로 누른다. 동기 스크롤은 두 패널의 `scrollTop`으로, 연결선 200개는 rAF마다 스크롤하며 프레임 간격(측정값은 테스트 주석 `connector-scroll-frames`에 남긴다)과 거의 모든 프레임에서 연결선이 다시 그려지는지 본다. 연결선은 장식이라(`aria-hidden`) 역할이 없어 이 속성들로 찾는다.
- **E2E 함정(가상화 행 `boundingBox`):** 패널 행은 react-virtuoso 가상화라 한 번에 크게 스크롤한 직후(스크롤 속도 600 초과, `SCROLL_SEEK_VELOCITY`)에는 행이 자리표시로 바뀌었다가 속도가 가라앉으면 돌아온다. 그 사이 `locator.boundingBox()`는 행을 찾은 순간 떼어져 `null`이거나 행이 없으므로, 스크롤한 뒤의 행을 바로 재지 않는다. 행 높이처럼 스크롤로 바뀌지 않는 값은 스크롤 전에 한 번 재서 쓰고, 꼭 스크롤 뒤에 재야 하면 `expect(async () => { … }).toPass()`로 행이 다시 그려질 때까지 기다린다(`compare-connectors.spec.ts`의 `rowHeight`). 부하(느린 CI 러너)에서만 드러나므로 `E2E_PORT=… pnpm exec playwright test <spec> --repeat-each=N --workers=8`에 CPU 부하를 줘 확인한다.
- **E2E 내보내기(Step 29):** `compare-export.spec.ts`는 pages-base ↔ pages-insert와 Rust golden 쪽 짝(`pages-insert.page-pairs.json`)에 손으로 둔 변경 셋으로 결과를 시드한다. 장 수 기대값은 ADR 0001 §14 장 고르기 규칙으로 손으로 센 리터럴이다. mock은 Rust처럼 장을 고르고(차이 쪽만·한쪽 배치·숨긴 종류, 넣을 장이 없으면 `EMPTY_REPORT`), 미리보기 그림은 장 번호를 쓴 PNG(장마다 다르다), 내보내기는 고른 폴더 바로 안의 이름만 받고 같은 이름이면 `이름 (2).pdf`로 만든다. 시드 `directoryPicks`(`(string | null)[]`)는 폴더 다이얼로그를 열 때마다 앞에서부터 하나씩 고르고(`null`은 취소, 다 쓰면 `/mock/exports`), 앱이 보낸 미리보기 요청은 `window.__E2E_MOCK_PREVIEWS__`에, 응답을 돌려준 수는 `__E2E_MOCK_PREVIEWS_SETTLED__`에 남는다. 내보내기 요청은 `__E2E_MOCK_WRITES__`에 `{ method: "exportComparePdf" | "exportAnnotatedPdf", request }`로 남는다. 늦은 응답은 `window.__E2E_HOLD_PREVIEW__`(요청할 때 그 값을 기다린다)와 `__E2E_RELEASE_PREVIEW__`로, 내보내는 중 화면은 `__E2E_HOLD_EXPORT__`로 붙잡는다(붙잡힌 동안 같은 작업 ID로 `cancelJob`이 오면 `CANCELLED`).
- **E2E 열기 다이얼로그·파일 크기:** 시드 `dialogPicks`(`string[][]`)를 주면 `pickFiles`가 부를 때마다 앞에서부터 한 목록씩 고른다(빈 목록은 취소, 다 쓰면 시드 파일을 모두 고른다). 슬롯마다 다른 파일을 고르는 비교 화면 테스트에 쓴다(`compare-slots.spec.ts`). 시드 파일의 `sizeBytes`는 `openFiles`가 돌려줄 크기이고, 없으면 바이트 길이다.
- **E2E 변환·병합 결과·저장 다이얼로그:** 시드 파일에 `convertedPath`를 주면 TIFF처럼 `openFiles`가 그 경로를 `pdfPath`로 돌려주고(Rust 캐시 폴더처럼 고르지 않아도 읽힌다), mock 병합은 Rust처럼 PDF가 아닌 소스를 `UNSUPPORTED_FILE_TYPE`으로 거부한다. 시드 `mergeOutput`(`{ outputPath, fileName }`)을 주면 `temp` 병합 결과가 그 경로·이름이 된다. 앱이 연 저장 다이얼로그 옵션(`{ fileName }`)은 `window.__E2E_MOCK_SAVE_DIALOGS__`에 차례로 남는다.
- **E2E 설정·오류 보고:** 개발 서버에서 플랫폼 설정(`getSetting`/`setSetting`)은 `localStorage`에 저장되므로 `page.reload()`로 재시작 후 유지를 확인한다(테스트마다 새 컨텍스트라 섞이지 않는다). 오류 보고는 테스트가 `addInitScript`로 `window.__E2E_ERROR_REPORTS__ = []`를 넣을 때만 켜지고(넣지 않으면 설정 없는 빌드처럼 버튼·안내가 없다), 실제로 보내지 않고 보내기 직전(경로를 지운 뒤)의 `{ message, stack, meta }`가 그 배열에 쌓인다(`app/providers/e2e-error-report.ts`). - **E2E 자동 업데이트:** 시드 `update`(`{ version, totalBytes, chunkBytes }`)를 주면 `checkForUpdate`가 그 새 버전을 알리고, 없으면 최신 버전일 때처럼 `null`이다. 받기(`download`)는 `chunkBytes`를 누계 진행률로 차례로 보낸 뒤 `window.__E2E_HOLD_UPDATE_DOWNLOAD__`(Promise)가 풀릴 때까지 끝나지 않는다(`__E2E_RELEASE_UPDATE_DOWNLOAD__`로 푼다). mock은 받기 전에 설치하면 실패한다. `failures.checkForUpdate`·`failures.downloadUpdate`(`PlatformErrorCode`, 업데이터 플러그인 실패는 `IPC_FAILED`)로 실패시키고, 앱이 부른 확인·받기·설치(`checkForUpdate`·`download`·`installAndRestart`)는 `window.__E2E_MOCK_UPDATES__`에 차례로 남는다. 진행 중인 작업 판단(`hasRunningWork`)은 병합 붙잡기(`__E2E_HOLD_MERGE__`)로 실제 흐름을 보고, 감싸는 호출 목록은 개발 서버 모듈(`shared/platform/running-work.ts`)을 `import()`해 끝나지 않는 호출로 확인한다(`app-update.spec.ts`). 확인 실패처럼 "토스트가 없다"를 볼 때는 다른 화면 갱신(파일 열기)을 기다린 뒤 한 번만 센다 — `toHaveCount(0)`은 저절로 닫히는 토스트가 사라질 때까지 기다려 통과해 버린다.
- **E2E 번역 플랫폼(Step 41):** 화면이 생기기 전이라 `translate-platform.spec.ts`가 앱이 주입한 플랫폼을 개발 서버 모듈(`shared/platform/current-platform.ts`의 `getPlatform()`)로 불러 호출한다. 시드 `apiKey`(`ApiKeyStatus`, 등록됐으면 키체인에 키가 있는 것으로 본다), `apiKeyChecks`(`(ErrorCode | null)[]`, `verifyApiKey`가 형식 검사를 통과할 때마다 앞에서부터 하나씩: `null`은 성공), `translateScripts`(`translatePdf`마다 `progress`를 차례로 보낸 뒤 `failCode`면 실패, 아니면 mock 검사(경로·쪽 범위·키) 뒤 `result`, 없으면 범위 쪽이 문단 없는 글자층 쪽인 결과). 진행 화면은 `window.__E2E_HOLD_TRANSLATE__`(Promise)와 `__E2E_RELEASE_TRANSLATE__`로 붙잡고, 붙잡힌 동안 같은 작업 ID로 `cancelJob`이 오면 `CANCELLED`다. 번역 요청은 `__E2E_MOCK_TRANSLATES__`에, 복사한 글은 `__E2E_MOCK_CLIPBOARD__`에, `saveApiKey`(`key`)·`deleteApiKey`·`editTranslatedParagraph`(`request`)·`deleteTranslationRecords`는 `__E2E_MOCK_WRITES__`에 남는다. 키를 저장하면 Rust처럼 설정 `translate.transferConfirmedOnce`가 `false`가 된다. mock은 글을 모르므로 계획은 문단·예상치 0과 언어 모름이고, 다시 번역·직접 고치기는 기억한 결과(mock 결과와 시드 `result`)의 문단만 찾는다(없으면 `TRANSLATION_RECORD_NOT_FOUND`). 키 원문이 DOM에 없음은 Step 43(`settings-dialog.spec.ts`)이 확인한다. 계획 시드는 Step 44(아래 "E2E 번역 옵션"), 다시 번역 시드는 Step 47(아래 "E2E 문단 동작")이 더했다.
- **E2E 설정 모달·키 모달(Step 43):** `settings-dialog.spec.ts`가 홈 톱니·번역 머리 톱니·`Meta+Comma`(Desktop Safari 장치의 UA가 macOS라 앱은 ⌘로 본다)로 연다. 키 확인은 `window.__E2E_HOLD_VERIFY_API_KEY__`(Promise, 부를 때의 값을 기다린다 — 형식 검사를 통과한 뒤 붙잡는다)와 `__E2E_RELEASE_VERIFY_API_KEY__`로 붙잡고, `verifyApiKey`를 부른 수가 `__E2E_MOCK_KEY_CHECKS__`에 남는다(키 원문은 남기지 않는다). 형식이 틀린 키는 앱이 먼저 막아 그 수가 늘지 않는다. 입력을 멈추기 전(디바운스)·붙여 넣기(`dispatchEvent("paste")` 뒤 `fill`, 바로 부른다)는 그 수로 본다. 늦은 응답 버리기는 붙잡은 첫 확인 뒤 붙잡기를 `undefined`로 바꿔 두 번째 확인이 먼저 시드 값을 쓰게 한다. 키 저장 뒤 `page.content()`에 키 원문이 없다. 새로고침 전 설정(예: 용어 `MAX_GLOSSARY_TERMS`개)은 `addInitScript`에서 `localStorage`에 `e2e-setting:<키>`로 한 번만 넣는다(새로고침마다 다시 넣으면 앱이 바꾼 값을 덮는다). 키 상태는 mock 메모리라 새로고침하면 시드로 돌아간다.
- **E2E 번역 옵션(Step 44):** `translate-options.spec.ts`가 홈 번역 카드로 문서를 넣어 옵션 화면을 연다. 시드 `translationPlans`(`{ match?, plan }[]`)는 `prepareTranslation`이 mock 검사(경로·쪽 범위)를 거친 뒤 앞에서부터 `match`(`path`·`sourceLanguage`·`range`·`includeScanPages`·`model`·`glossaryCount` 중 적은 것만, 용어집은 정규화한 용어 수)가 맞는 첫 계획을 돌려주고(쓰고 나도 남는다), 맞는 것이 없으면 mock 계획(문단·예상치 0, 언어 모름)이다. 옵션이 쌓이므로 나중에 바꿀 옵션의 시드를 앞에 둔다. 앱이 보낸 계획 요청(`{ path, options }`)은 `window.__E2E_MOCK_PLANS__`에, 응답을 돌려준 수는 `__E2E_MOCK_PLANS_SETTLED__`에 남는다. 늦은 응답은 `window.__E2E_HOLD_PLAN__`(요청할 때의 값을 기다린다)과 `__E2E_RELEASE_PLAN__`으로 붙잡고, 붙잡기를 `undefined`로 바꾼 뒤의 요청이 먼저 오게 해 앞 응답을 버리는지 본다. 실행 전 확인 값은 `dt`·`dd`(카드는 `complementary` "실행 전 확인"), 막힘 이유는 "번역 시작" 버튼의 접근 가능한 설명(`toHaveAccessibleDescription`)으로 본다. 외부 전송 확인 기록(`translate.transferConfirmedOnce`)은 `localStorage`의 `e2e-setting:` 값으로 넣고 읽는다. 시작은 `__E2E_MOCK_TRANSLATES__`(요청·옵션)로 본다. 번역이 끝나면 결과 화면이 뜨므로 옵션 화면을 다시 보려면 머리의 "옵션으로 돌아가기"를 누른다.
- **E2E 번역 진행(Step 45):** `translate-progress.spec.ts`가 `translateScripts`의 진행률(ADR 0002 §9 공식으로 손으로 셈한 값, 단계 %와 전체 %가 다르게 고른다)과 `__E2E_HOLD_TRANSLATE__`로 진행 카드(`region` "전체 진행률", 작업 행은 `list` "작업별 진행"의 `listitem`, 막대는 `progressbar` "<단계> 진행률")를 본다. 다른 모드 상태바는 `footer`의 `status` "번역 중 n%"다. 취소는 `__E2E_MOCK_WRITES__`의 `cancelJob` 기록과, 취소 뒤 다시 받은 계획의 이어하기 문구로 본다. 같은 옵션인데 번역 뒤에 다른 계획을 주려면 계획 시드에 `once: true`를 주어 앞에 둔다(한 번 쓰면 지운다). 실패는 `failCode`로 내고 `alertdialog` "번역하지 못했어요"의 문구·멈춘 곳·코드, "다시 시도(이어서)"의 두 번째 요청(작업 ID만 다르다)을 본다. 키 모달이 열리면 뒤 화면이 `aria-hidden`이라 역할로 찾지 못하므로 모달을 닫은 뒤 옵션 화면을 본다.
- **E2E 번역 결과(Step 46):** `translate-result.spec.ts`가 `translateScripts[].result`(계약 JSON과 같은 모양, 문서 전체 쪽 배열)로 결과 화면을 연다. 패널은 `list` "원문"·"번역"이고 문단 행은 그 `listitem`, 고른 행은 `aria-current="true"`다. 같은 번호 행 맞춤은 두 목록의 n번째 행 `getBoundingClientRect()` 위 끝·높이가 1px 안인지와, 한쪽 글이 긴 행이 짧은 행보다 높은지(한쪽만 길어도 행이 같이 높아진다)를 배율을 바꿔 가며 본다(행은 가상화하지 않는다). 쪽 이동은 `textbox` "쪽 번호"의 값, 배율은 `status` "배율"과 행의 계산된 `font-size`, 용어집은 `dialog` "용어집"으로 본다. 팝오버가 패널 머리를 덮으므로 바깥 누르기는 상태바를 누른다.
- **E2E 문단 동작(Step 47):** `translate-paragraph-actions.spec.ts`가 결과 시드 위에서 문단 동작을 본다. 시드 `retranslateScripts`(`{ failCode?, result? }[]`)는 `retranslateParagraph`를 부를 때마다 앞에서부터 하나씩 써서 `window.__E2E_HOLD_RETRANSLATE__`(Promise, 부를 때의 값을 기다린다)와 `__E2E_RELEASE_RETRANSLATE__`로 붙잡은 뒤, `failCode`면 그 코드로 실패하고 아니면 mock 검사(경로·기록·문단·키) 뒤 `result`(`RetranslateResult`, 실패·거절 문단도 넣을 수 있다. 없으면 기억한 문단 그대로·사용량 0)다. 앱이 보낸 다시 번역 요청은 `__E2E_MOCK_RETRANSLATES__`에 남는다. 동작 줄은 번역 행 안 `group` "문단 동작", 진행 표시는 그 행의 `status` "다시 번역하는 중", 고치기 입력 칸은 `textbox` "번역 고치기", 토스트는 `[data-sonner-toast]`로 찾는다. 다시 번역 중 막힌 "번역 시작"은 옵션 화면의 접근 가능한 설명으로 본다(옵션 화면에서 결과로 돌아오는 길은 "결과 보기"뿐이라 상태바는 결과 화면에 있을 때 본다). 동작 줄·입력 칸으로 높아진 행도 `expectRowsAligned`로 같은 번호 행 맞춤을 본다.
- **E2E 제3자 고지:** 시드 `thirdPartyNotices`에 저장소의 `THIRD_PARTY_NOTICES.md` 원문을 넣으면 `readThirdPartyNotices`가 그 원문을 돌려주고, 넣지 않으면 Rust처럼 `RESOURCE_UNAVAILABLE`로 실패한다(`third-party-notices.spec.ts`).
- **E2E 좌표 일치(pdf.js 단독):** 화면이 아직 없는 엔진 결과는 `page.evaluate` 안에서 개발 서버가 내주는 `src/renderer/shared/lib/pdfjs/pdfjs-setup.ts`(앱과 같은 Worker·cMap 설정)를 `import()`해 pdf.js로 직접 확인한다. 앱에 테스트 전용 코드를 두지 않는다. Rust golden과 픽스처 PDF는 사본 없이 `crates/pdf-core/tests/`에서 그대로 읽는다(`text-box-geometry.spec.ts`).
- E2E 셀렉터는 역할·접근 가능한 이름(`getByRole`) 우선이고, 없을 때만 `data-testid`를 최소로 둔다(지금은 `document-card`, `page-card`, `drop-indicator`). 정렬 카드는 `getByRole("button", { name: "<파일 이름> 문서" | "<파일 이름> <쪽>쪽" })`로 찾고, 재정렬 진행은 dnd-kit live region(`getByRole("status")`) 문구로 기다린다.
